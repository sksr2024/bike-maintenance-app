# `整備予定`を`整備記録`とは独立したエンティティとして新設する

将来行う整備は、ユーザー自身ではなくショップ側が期日を決めることがほとんどであり、既存の`整備記録`（`performed_on`・`mileage_km`など実施済みの確定した事実を表す項目を持つ）とは性質が異なる。同じテーブルに「予定/実施済み」フラグを持たせる案も検討したが、予定特有の状態（未確定であること、通知済みかどうか等）を実施記録用のスキーマに押し込むことになり既存機能のシンプルさを損なうため、独立したエンティティ`整備予定`（整備種別・期日（日付のみ）・メモを持つ）として新設することにした。整備種別は既存の固定リストを再利用するが、走行距離ベースでの予定管理は対象外とする。`整備記録`の登録時に対応する`整備予定`を選んで完了扱いにできる任意の緩やかな連携を持たせるが、連携は必須ではなく、`整備予定`は手動でも完了・削除できる。期日を過ぎても未完了の場合の督促（再通知）は行わない。
