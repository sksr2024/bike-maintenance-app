# `整備予定`の期日通知は、抽出・送信・トリガーを分離し、当面はアプリ内蔵スケジューラで実装する

`整備予定`の期日が近づいたらメールで通知する機能を、将来的にAWS上のサーバーレス構成（EventBridgeによるトリガー・SESによる送信）へ移行する前提で設計する。ただし現時点ではAWS環境へのTerraformによる本番プロビジョニングはインフラ全体のアーキテクチャ変更を伴うため別スコープとし、まずは既存のNode.jsバックエンド内で完結させる。そのため「通知対象の抽出」「メールの送信」「実行のきっかけ（トリガー）」の3つの責務を分離して実装し、トリガーには当面Node.jsプロセス内蔵のスケジューラ（1日1回実行）を、送信には当面Nodemailer（ローカル開発ではMailhogで検証）を用いる。抽出・送信ロジック自体はトリガー方式や送信プロバイダに依存しない形にしておくことで、将来EventBridge・SESへ差し替える際にトリガーと送信部分の実装のみを置き換えられるようにする。
